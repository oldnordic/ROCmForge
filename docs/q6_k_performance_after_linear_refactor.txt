## Analysis

**Performance Impact:** Minimal (-0.8%)
- The linear refactoring maintains performance parity
- Graph capture adds minimal overhead for this model size
- No GPU crashes or errors with graph enabled

**Why No 2.2-3.7x Improvement?**

The expected 2.2-3.7x improvement was based on:
- Baseline: 134 tok/s (from documentation)
- Target: 295-496 tok/s (2.2-3.7x improvement)

However:
1. **Model size limitation:** 0.5B model has only 3 blocks, limiting graph capture benefits
2. **Already optimized:** Current kernel already had device function pattern
3. **Small model:** Graph capture overhead is relatively high for tiny models

**Graph Capture Benefits:**
- ✅ Eliminates kernel launch overhead (more significant on larger models)
- ✅ Enables future optimizations (batch processing, pipelining)
- ✅ Consistent with Q4_K pattern (maintainability)
- ✅ No GPU crashes with multi-token prompts
